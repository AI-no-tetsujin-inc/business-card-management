# 文字起こし → 人物ごとの情報（人物像）の JSON

社内アプリの「人物情報」に取り込む JSON を作る。アプリは JSON の `card_id` か「氏名＋会社」で名刺の人を特定し、はっきりした人で確信度が 0.7 以上のものは自動で反映、それ以外は「確認待ち」にする。

## 入力

- 会議の文字起こし・議事録・メモ（テキスト・ファイル・貼り付けのどれでも）
- あれば、アプリの「人物情報 → 1. まとめて出力」でコピーした Markdown。各人の見出しに `[id: …]` がある。**これがあれば人の特定はこの ID で行う**（なければ氏名と会社だけで書く）

名刺管理のコネクタ（MCP）がつながっている場合は、JSON を作らずに `export_people_profiles` で人物情報を取り、`add_person_insights` で直接入れてよい（項目は下の JSON と同じ）。

## 手順

### 1. 登場する社外の人を洗い出す

- 社内メンバー（@ainotetsujin.com）は対象外。
- 人物情報の Markdown にいる人は、その `[id: …]` を `card_id` に入れる。文字起こしの誤変換（例:「おとの」「乙野」）は、会社と文脈が合うときだけ同じ人とみなす。
- Markdown にいない人は `card_id` を空にし、氏名と会社を書く（アプリで確認待ちになる）。
- 名前が出てこない人（「先方の部長」など）は、会社と役職が分かり Markdown で1人に絞れるときだけその人にする。絞れなければ `name` に「（部長・氏名不明）」のように書き、confidence を 0.5 以下にする。

### 2. 人ごとに、分類して書き出す

| category | 分類 | 書くこと |
|---|---|---|
| role | 立場・役割 | 決裁者・推進者・窓口・影響者・利用者・反対者 など、社内での立場と権限（「予算の決裁権がある」など） |
| attitude | 温度感 | 当社・提案への姿勢（好意的・中立・慎重・反対）と、そう読める理由 |
| status | 今の状況 | 案件の進み具合・社内の事情・最近の動き・異動や体制の変化 |
| personality | 性格・人柄 | 話し方・考え方・意思決定のしかた（発言から読めることだけ） |
| interest | 関心・課題 | 困っていること・関心のあるテーマ・求めていること |
| caution | 気をつけること | 好み・NG・配慮が必要なこと・地雷 |
| relation | 人間関係 | 誰の上司・部下・誰と近い・誰の紹介 |
| other | その他 | 上のどれにも当てはまらない、覚えておくべきこと |

- 1件は1〜2文。主語（その人）は書かなくてよい。例: 「来期の予算は11月の役員会で決まる。今期中の発注は難しい」
- `evidence` には根拠になった発言・記述を短く引用する（文字起こしの言い回しのまま）。
- **書かれていないことは推測で足さない。** 性格や温度感は、はっきり読み取れる発言があるときだけ書く。1回の会議の印象だけなら confidence を 0.6〜0.7 にする。
- 同じ人・同じ分類で同じ内容を何件も書かない（まとめる）。
- 悪口・評価だけの言葉（「面倒な人」など）は書かない。事実と、仕事で役立つ配慮に言い換える（「結論から話すと話が早い」など）。

### 3. JSON を書き出す

```json
{
  "source": "2026-10-27 サンプル自動車 定例会議",
  "date": "2026-10-27",
  "items": [
    {
      "card_id": "（Markdown の [id: …]。分からなければ空文字）",
      "name": "山本 太郎",
      "company": "サンプル自動車株式会社",
      "category": "status",
      "text": "来期の予算は11月の役員会で決まる。今期中の発注は難しい",
      "evidence": "予算は11月の役員会次第なので、今期はちょっと…",
      "confidence": 0.9
    }
  ]
}
```

- `source`: どの会議・資料か（日付＋会議名）。`date`: その日付 YYYY-MM-DD（不明なら空文字）。
- `confidence`: 人の特定と内容の確からしさ 0〜1。card_id があり発言がはっきりしていれば 0.8〜0.95。
- ファイル名は `人物情報_YYYYMMDD.json`。Claude.ai なら `/mnt/user-data/outputs/`、Claude Code なら文字起こしと同じフォルダに保存する。文字コードは UTF-8。

### 4. 結果を伝える

- 人ごとに、入れた分類と内容を短い表で見せる。
- card_id を入れられなかった人（確認待ちになる人）と、confidence が 0.7 未満の項目を、理由と一緒に箇条書きにする。
- 次の手順を伝える: アプリの「メニュー → 人物情報」を開き、「2. 文字起こしなどから振り分けて入れる」でこの JSON ファイルを選ぶ（または中身を貼り付けて「取り込む」）。確認待ちは「3. 確認待ち」で人を選ぶ。

## してはいけないこと

- 社内メンバーの情報を入れる
- 文字起こしにないことを推測で書く・盛る
- 個人のプライベートな事情（健康・家族など）を、仕事上の配慮に必要な範囲を超えて書く
