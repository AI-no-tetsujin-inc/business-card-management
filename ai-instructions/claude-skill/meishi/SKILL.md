# 名刺管理アプリの使い方（段取り）

社内の名刺・人物・会社・議事録・顧客請求・社内請求・サブスクのデータは「名刺管理」コネクタにある。ルール（同じ人の自動統合、表記の正規化、権限）はアプリ側で処理されるので、ここでは段取りだけを守る。

## 共通のルール

- 人物を指定するときは、必ず先に `search_people` で探し、`person_id` を使う。同じ名前が複数いたら、会社・部署を示してどの人か聞き返す。推測で選ばない。
- 書き込み（登録・更新・メモ・送付／連絡のチェック）の前に、何をするかを1行で伝えてから実行する。
- 名刺に書かれていない項目は空のまま送る。会社名は名刺の表記どおり（「株式会社」を省略しない）。
- 削除はできない。不要な名刺は「アプリのごみ箱に入れてください」と案内する。

## 名刺を登録する（写真を受け取ったとき）

1. 写真から項目を読み取り、読み取り結果を短く見せる（自信のない文字は「？」を付けて確認する）。
2. `register_person` で登録する。交換日・場所がわかれば `met_on` `met_place` に入れる。
3. 結果ごとの対応:
   - `created` / `merged`: 返ってきた `card_image_upload_url` を「このリンクから同じ写真を選ぶと名刺画像が保存されます（15分有効）」と案内する。`merged` で更新された項目（異動・昇進など）があれば伝える。
   - `needs_confirmation`: 候補を見せて「同じ人ですか？」と聞く。同じなら `merge_into`、別人なら `force_new: true` で再実行する。

## メールを送る・連絡する

1. `search_people` で相手を特定し、必要なら `get_person` で過去のやり取り・メモを確認する。
2. Gmail コネクタで**下書き**を作る。送信は利用者が確認してから。宛名は「会社名 部署 役職 氏名 様」の形にする。
3. 送信したら `add_note` で「〇/〇 〜についてメール送信」と記録する。

## 打ち合わせの準備

1. `get_company` で会社の人物・案件・契約・最近の請求書を確認する。
2. 参加者ごとに `get_person` で過去のやり取りとメモを見る。
3. 「前回決まったこと」「こちらの宿題」「確認したいこと」の3つにまとめて伝える。日程調整は Google カレンダーコネクタで行う。

## 打ち合わせのあと

- 相手について覚えておくことは `add_note` で人物に残す。
- 議事録は Mac の Voiss で録音すれば自動で入る（下の「議事録」）。関係性マップはこのアプリでは扱わない。

## 議事録

- 会議の録音は Mac の Voiss で行い、止めると自動でアプリに届く。アプリが要点・決まったこと・ネクストアクションを抜き出し、Google Drive の「議事録」フォルダに保存して、Google Chat の議事録スペースに知らせる。AI から取り込みの操作をする必要はない。
- 「先週のサンプル自動車の打ち合わせで決まったことは？」→ `list_minutes`（`company`、`from` / `to`、`keyword`）で探し、`get_minutes` で要点・決まったこと・ネクストアクションを読む。
- 目的に合わせた取り出し（「ネクストアクションだけ」「〇〇さんへの報告文」「〇〇の件で何と言っていたか」）は、`get_minutes` を `include_transcript: true` で呼び、全文を読んで答える。長い会議は `transcript_offset` で続きを読む。
- 文字起こしには誤変換があり、話者の区別はない。人名・会社名は `search_people` や `get_company` の表記に合わせ、推測で補わない。答えには根拠の発言の時刻 [h:mm:ss] を添える。
- ネクストアクションは `list_tasks` に入っている。済んだと言われたら `complete_task`。

## 顧客請求（見積書 → 契約 → 請求書作成 → 送付 → 連絡）

- 「10月分の請求書を作って」→ まず `prepare_customer_invoices`（`period: "2026-10"`）で顧客ごとの明細と金額（税込）を一覧で見せ、「この内容で作成しますか？」と確認する。
- OK なら `create_customer_invoices`（同じ `period`）。請求日の指定があれば `issue_date`。PDF が Google Drive（顧客請求書/YYYY年M月分/顧客名）に保存されるので、番号・金額・Drive のリンクを伝える。1件数秒かかる。
- 文言（対象期間・内容・備考・請求日）を直したいと言われたら `update_customer_invoice` で直し、もう一度内容を見せて確認を取る。誰が頼んでもよい。毎月の金額そのもの（契約）を変える場合はアプリの「契約」タブで管理者が行う。
- 作成は必ず確認を取ってから。確認なしに `create_customer_invoices` を呼ばない。
- 作成したら、担当者（送付先・連絡手段）を伝え、送付・連絡が済んだら知らせてもらう。「送った」「連絡した」と言われたら `check_customer_invoice`（`sent` / `contacted`）。チェックできるのは担当者と管理者だけ。
- 状況の確認は `list_customer_invoices`。入金の確認は扱わない。

## 社内請求・経費（登録された社内請求対象者のみ）

- 「10月分の稼働分の請求書を作って」→ `submit_internal_claim`（`period: "2026-10"`, `kind: "work"`, `member` は本人なら省略）に `dry_run: true` を付けて中身（品目・金額・番号・支払日）を見せ、確認が取れたら `dry_run` なしで提出する。
- 立替経費は `kind: "expense"`。アプリに登録済みの未請求の明細をまとめる。領収書と金額が合わない・領収書がないと止まるので、その内容を伝えてアプリで直してもらう。
- 社内請求の対象者はシステムの登録内容で確認する。誰の分かわからなければ聞き返す。振込先が未登録だと提出できない。
- 月末締め・翌月1日提出・翌月5日払い。提出状況は `list_internal_claims`。

## 契約・サブスク

- 「契約しているサービスは？」「個人名義のものは？」→ `list_subscriptions`。個人名義・個人立替のものは会社名義・法人カードへの移行対象として伝える。
